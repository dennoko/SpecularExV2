# SpecularExV2 エディタ負荷（マスクパック・監視）対策計画

作成日: 2026-09-27  
対象リビジョン: `b951c81`  
対象ファイル: `Editor/SpecularExPackedMaskWatcher.cs`、`Editor/SpecularExPackedMaskStore.cs`、`Editor/SpecularExV2Inspector.cs`（パック状態表示）

## 1. 目的と前提

Unity での普段の作業中に起きる、SpecularExV2 が原因の待ち時間をなくす。具体的には AssetDatabase のプログレスバー、同期処理による短いフリーズ、連鎖するインポートを減らす。

守る前提は次のとおり。

- **正しさは変えない。** パック画像は「元マスクスロットから導出されるデータ」であり、`EnsureAll` を冪等に保つ設計（`SpecularExPackedMaskStore.cs:13–21`）は維持する。
- **ビルド経路（VRCSDK フック / NDMF）は常に正確に判定する。** D・H の検証省略用キャッシュは、ビルド・手動リビルド・「Update All Materials」では使わない。保存の有無（`persist`）とキャッシュ利用の可否は別の引数で制御する。
- **監視対象と削除前の依存情報を失わない。** ドメインリロード後も監視を復元し、削除前の情報が不明な場合は全件確認へフォールバックする。ビルド時の修復だけを理由に、エディタでの更新漏れを許容しない。
- `OnPreprocessTexture` や `GetVersion` を持つ AssetPostprocessor は追加しない。追加すると全テクスチャのインポート依存になる（`SpecularExPackedMaskWatcher.cs:239–242`）。

## 2. 問題の整理（コード確認済み）

事前調査の5項目をコードで確認した。あわせて、調査で抜けていた点（★）も加えている。

| # | 重大度 | 発生契機 | 現状の処理 | 根拠 |
|---|---|---|---|---|
| 1 | 高 | **関係のない** テクスチャや `.asset` のインポート・削除 | `FindAssets("t:Material")` で全マテリアルを列挙し、そのそれぞれに `GetDependencies` を実行。削除時は SpecularEx マテリアルを全てロードして再チェックする | Watcher `131–135, 171–181`、Store `387–397` |

補足:

- `TextureExtensions` と `MaterialContainerExtensions` の両方に `.asset` が含まれる。そのため Modular Avatar や VRChat の各種 `.asset` の保存でも #1 の全件走査が走る。
- 「EnsureAll は冪等なので、広すぎる発火でも安い」というコメント（Watcher `13–14`）は、#6 と InputKey の依存ハッシュ取得があるため、実際には成り立っていない。対策の中心は **発火を絞ることと、何もしない場合の処理を実際に安くすること** の2つ。

## 4. 各対策の詳細

### M. 計測用の仕組み（フェーズ0）

- `Unity.Profiling.ProfilerMarker` を `Watcher.Process`、`CollectSceneMaterials`、`CollectAffectedAssetMaterials`、`EnsureAll`（Pass 1 / インポート設定 / Pass 2）、`GetState` に付ける。
- `EditorPrefs` のフラグ（例: `SpecularExV2.DebugTiming`）が有効なときだけ、`Process` ごとに対象マテリアル数・経過時間・書き込み数・再インポート数を `Debug.Log` に出す。既定は無効にし、出荷時も残す。
- 計測シナリオ（改修前後で比較する）:
  1. 無関係の PNG を外部ツールで上書き保存する
  2. 無関係のテクスチャを削除する
  3. SpecularEx マテリアルのスライダーを3秒ドラッグする
  4. SkinnedMeshRenderer の BlendShape をドラッグする
  5. スクリプトを1行変更してコンパイルする
  6. アバターを含むシーンを開く
  7. マスクスロットに新しい 2048² テクスチャを割り当てる
- 計測用プロジェクトの規模: マテリアル 2000 件以上（SpecularEx 以外を含む）、SpecularEx マテリアル 50 件程度。
- インデックス構築前・構築後・リロード後を分けて測り、構築時間、監視再登録時間、キャッシュ命中数、全件確認へのフォールバック回数と理由も記録する。初回削除の全件確認と、通常時の負荷削減を区別して評価する。

### A. オブジェクト変更イベントを絞る（フェーズ1）

**変更:** `OnChangesPublished` の `ChangeAssetObjectProperties`、`ChangeGameObjectOrComponentProperties`、`CreateGameObjectHierarchy` の3つで、`Request(m)` の代わりに `RequestIfSlotsChanged(m)` を呼ぶ。

**補足:**

- `_slotState` の比較対象に **パック先スロット（`_CustomMaskPacked` / `_CustomMaskPacked2`）のインスタンス ID も含める**。こうすると、Undo でパック画像への参照だけが戻った場合も検出できる。自分の `SetTexture` によっても状態が変わるため、`EnsureAll` の最後で `_slotState` を最新の値に更新し、自分の変更で再び発火しないようにする。
- 現在の `int` ハッシュは衝突し得る。スロット ID の配列（`int[10]`）をそのまま比較する方式に変える。
- ソース画像の **内容** が変わった場合はスロット参照が変わらないため、A では検出できない。これは従来どおりテクスチャのインポートイベント（#1 の経路）で扱う。
- 初めて見るマテリアルは状態がないので、1回だけ `Request` される。これは従来と同じ。

**効果:** スライダー操作と BlendShape 操作での毎フレームの `EnsureAll` がなくなる。

### B. 自分で保存した `.mat` による再発火を抑える（フェーズ1）

**変更:** `EnsureAll` の `SaveAssetIfDirty` の直前に、そのパスを `SpecularExPackedMaskWatcher` の `_selfSaved` に登録する。自己保存に対応するイベントと確認できた場合だけ、同じコンテナの再パック要求を1回省き、登録を削除する。F の依存インデックス更新、監視記録の更新、G・H の無効化は省略しない。

**補足:** 保存と Postprocessor の通知タイミングは実機で確認し、「次の通知が必ず自己保存」とは仮定しない。保存直後の状態との照合と登録の失効処理を設け、例外・通知なしの場合も登録を残さない。他ツールやユーザーによる変更と区別できなければ通常どおり要求する。次の `Process` がなくても登録が失効するようにし、後続の無関係な保存を抑制しない。

### C. 監視対象の再登録とパック検証を分離する（フェーズ2）

**変更:** シーン走査での監視対象の登録と、`EnsureAll` によるパック検証を分離する。静的コンストラクタからの走査要求は残し、ドメインリロード後にロード済みシーンと Prefab Stage のマテリアルを再登録する。`SessionState` の走査済みフラグだけで走査を省く方式は採用しない。

**補足:**

- `_inMemory` などの static な監視記録はリロードで失われる。F で復元するコンテナパスのインデックスだけでは、シーン埋め込みマテリアルや未保存の編集状態を復元できない。
- 再登録は Inspector を開いているかに関係なく行う。F 導入後はソースとパック先の現在のパスを記録する。再登録前に届いたイベントはキューに保持し、登録後に処理する。削除前の記録を復元できない場合は対象を限定せず再検証する。
- リロード直後は H の検証済み状態も失われるため、初回検証を行う。リロードをまたいでインスタンス ID や走査済みフラグだけを信用して検証を省かない。旧プレビューからの移行やパッカー更新時の再検証も維持する。
- Postprocessor が積んだ未処理イベント・監視記録・F のインデックスは、`AssemblyReloadEvents.beforeAssemblyReload` でまとめて `SessionState` に保存し、リロード後の静的コンストラクタで復元する。スクリプトとテクスチャが同じリフレッシュで取り込まれると `Process` の前にドメインリロードが入り、static のキューが失われるため。復元した値はすぐに `SessionState` から消し、古い値を再利用しない。同一セッション内のリロードなのに保存値がない、または復元に失敗した場合は、削除前の情報が不明として扱い、次の削除で F の全件確認へフォールバックする。
- `sceneOpened` と `prefabStageOpened` は残す。同一ドメイン内では H の有効な記録があるマテリアルの検証を省けるが、Renderer の列挙と監視への登録は行う。コンパイル直後の全検証省略は今回の目標に含めない。

### D. インポート設定の確認をキャッシュする（フェーズ1）

**変更:** `EnsureAll` に既定値 `false` の `bool useCache` 引数を追加し、Watcher 経由だけ `true` にする。キャッシュ利用時の `EnsureImportSettings` の対象を次の2種類に限る。

1. その呼び出しで新しく書き込んだパス
2. このドメイン内でまだ確認していない、または無効化されたパス（`static HashSet<string> _verifiedImportSettings`）

確認と必要な再インポートが成功したパスだけを `_verifiedImportSettings` に追加する。生成ファイルのインポート・削除・移動時は旧パスを含めて無効化する。現行 Postprocessor の生成ファイルを除外する分岐より前にこの処理を置き、G・H の無効化にもつなげる。importer の取得失敗や再インポート失敗を検証済みとして扱わない。

**補足:** ビルドフック、NDMF、手動リビルド、「Update All Materials」は `useCache: false` とし、全対象パスの設定を確認する。`rebake: true` の場合もキャッシュを迂回する。H 導入後もこの共通のキャッシュ利用条件を維持する。

### E. `ShaderFolder()` をキャッシュする（フェーズ1）

**変更:** 結果を static にキャッシュする。値が `null`（見つからない）のときはキャッシュせず、次回もう一度探す。Postprocessor で `ShaderAssetGuid` のファイルが移動・削除されたときはキャッシュを消す。

### F. 逆依存インデックスで通常時の全件走査を減らす（フェーズ2）

**現状の問題:** Unity には「このテクスチャを使っているマテリアル」を引く API がない。そのため、テクスチャのイベントが来るたびに全マテリアルの依存関係を調べている。

**変更:** Watcher に、**ソースおよび生成マスクのパスから、それを使う SpecularEx コンテナのパス一覧を引くインデックス** を持たせる。

```
Dictionary<string texturePath, HashSet<string containerPath>> _texToContainers
Dictionary<string containerPath, string[] texturePaths>       _containerToTex   // 更新時の差分用
```

- **構築:** 最初にテクスチャのイベントが来たときに1回だけ作る（遅延構築）。やり方は現在の `CollectAffectedAssetMaterials` と同じで、`FindMaterialContainerPaths` を列挙し、`GetDependencies(path, false)` を取り、`UsesSpecularExShader` に当てはまるものだけを登録する。依存関係の中に生成マスクのパスがあれば、それも登録する（生成マスクが削除された場合に対応するため）。構築にかかった時間は M のログに出す。
- **ドメインリロード対策:** 構築・差分更新したインデックスを `SessionState.SetString` に JSON で保存する。形式バージョンと有効性を管理し、復元失敗・更新漏れの疑い・保存サイズ超過（例: 1MB 超）の場合は古い保存値を破棄して未構築として扱う。再構築だけでは削除前の情報は戻らないため、削除イベントは以下のフォールバックで処理する。
- **差分更新（Postprocessor）:**
  - まず変更バッチと更新前のインデックスから影響先を確保し、その後に依存関係を更新する。同一バッチ内の削除とコンテナ再インポートでも、検索前に古い依存を消さない。Postprocessor はイベントをキューに積み、ロードや差分更新は `Process` で行う。
  - コンテナがインポートされたとき: `_containerToTex` の古いエントリを取り除き、新しい依存関係で登録し直す。SpecularEx でなくなったコンテナは取り除く。
  - コンテナが削除されたとき: 取り除く。
  - 移動したとき（`moved` / `movedFrom`）: キーと値のパスを書き換える。テクスチャの移動も同じように扱う。
- **検索:** 有効なインデックスでは、インポートまたは削除されたテクスチャのパスから当たったコンテナだけをロードする。削除の限定検索は、そのイベントより前の有効な依存情報を保持している場合に限る。
- **削除時のフォールバック:** 未構築時の最初のイベントが削除の場合、復元に失敗した場合、削除前の情報の完全性を保証できない場合は、従来どおり全 SpecularEx コンテナと監視対象マテリアルを確認する。ロード済みシーン・Prefab Stage の監視も再登録し、H を迂回して確認する。その後に最新のインデックスを構築する。ソースと生成マスクの両方の削除に適用する。
- **インメモリのマテリアル:** `_inMemory` を `Dictionary<Material, TrackedPaths>` に変え、`TrackedPaths` に最後に確認したソースとパック先の両方のパスを保持する。削除で参照が missing になっても旧記録から照合できるよう、影響先の確保前に上書きしない。保存されていない `.mat` の編集も拾えるよう、監視再登録と `Process` で扱う全マテリアルを記録し、割り当て後に更新する。移動時は記録のパスも更新し、破棄されたマテリアルは除去する。

**リスクと対策:**

- インデックスに漏れがあると、ソースを変えてもパック画像が更新されない。整合性に疑いがある場合の全件確認を必須とし、ビルドフックや手動メニューだけに修復を委ねない。「Update All Materials」ではキャッシュを迂回して検証し、依存インデックスも作り直せるようにする。
- B の自己保存イベントでも依存更新を行う。保存済みコンテナとインメモリ記録の両方から影響先を集め、H の無効化対象にも両方を含める。
- `.asset` はテクスチャ側・コンテナ側の両方として扱う。NDMF の一時出力フォルダーにある `.asset` も対象になるが、これは `AreSourcesStripped` によって何もせず抜けるため、正しさへの影響はない。必要なら除外フォルダーを追加する。

### G. Inspector の状態キャッシュ（フェーズ2）

**変更:** `GetState` の結果を、マテリアルごとに次のキーでキャッシュする。

- スロットとパック先のインスタンス ID（A と同じ配列）
- Watcher が持つ **アセット世代カウンタ**（Postprocessor で関係するインポートや削除を見るたびに加算する）

キーが一致すればキャッシュを返す。あわせて `DrawPackingStatus` 内の `List<Material>` の確保も、キャッシュを使い回すように変える。

### H. 検証済みマテリアルのキャッシュ（フェーズ2）

**変更:** `EnsureAll` にエディタ専用の近道を加える。`Dictionary<Material, VerifiedState>` に「スロット ID 配列、パック先の ID、確認時点のアセット世代」を記録する。次回の呼び出しで次の条件がすべて成り立てば、`InputKey` の計算・`File.Exists`・ロードを省く。

1. 配列が一致している
2. その後のソース・生成マスクのイベントでキャッシュが無効にされていない（F のコンテナ検索とインメモリ記録の照合の両方を使う）
3. 全ソースが保存済みアセットで、前回の必要な各パックの `InputKey` が取得できている
4. 前回のベイク・インポート設定確認・ロード・割り当てがすべて成功している

**補足:**

- D で追加した `useCache` を共用する。Watcher 経由だけ `true` とし、ビルドフック、NDMF、手動リビルド、「Update All Materials」、F のフォールバックは `false` にする。`rebake: true` も常に迂回する。
- 未保存の `Texture2D` や `RenderTexture` は同じ参照のまま内容が変わり、インポートイベントも来ないため、検証済みキャッシュに登録しない。従来どおり `EnsureAll` が呼ばれた際にベイクして内容で判定する。内容変更の常時監視を新たに保証するものではない。
- 成功状態はマテリアル単位で、処理後の参照を使って登録する。一部のパックでも失敗した場合は登録せず、古い検証済み状態も消す。自動リトライは追加せず、次の要求または手動操作で再確認できるようにする。
- 単純にするため、アセット世代が変わったら全件を消す方式で始めてもよい。まずは結果の正しさを優先する。
- 同一ドメインでのシーン・Prefab Stage の再走査では、有効な記録があるマテリアルの検証を参照比較で省ける。C の監視再登録そのものや、リロード直後の初回検証は省かない。

### I. インポートを1回にする（フェーズ3・要検証）

**現状:** PNG を書いて `ImportAsset` を呼ぶと、既定の設定で圧縮され、その後 `SaveAndReimport` で BC7 または ASTC に再圧縮される。2048² の BC7 圧縮は数秒かかることがあり、それが2回起きる。

**方針:** `<path>.meta` が存在しない場合だけ、新GUID付きの `.meta` を初回インポート前に書く。既存 `.meta` は上書きしない。`rebake: true` によるPNGの上書きと、PNGだけが欠損して `.meta` が残っている場合は、既存GUIDを保持する。

- `.meta` のテンプレートは C# の文字列として持つ。GUID の部分には `GUID.Generate()` の値を入れる。テンプレートの元は、出荷時の Unity バージョン（2022.3）で生成されたパック画像の `.meta` から、`TextureImporter` の必要な項目を抜き出して作る。
- 最初のインポートが終わったら、従来どおり `ApplyImportSettings` で確認する。違いがあれば `SaveAndReimport` にフォールバックする。こうすればテンプレートが Unity のバージョン差で一部無視されても、正しさは保たれる。フォールバックが起きたことは M のログに出す。

**事前に確かめること:**

1. 一部の項目しか書かれていない `.meta` を Unity 2022.3 が受け入れ、足りない項目を既定値で補うか。
2. `platformSettings`（Standalone / Android / iPhone）の上書きが初回のインポートで反映されるか。
3. `StartAssetEditing` の中で `.meta` と PNG を書いてから `ImportAsset` した場合に、GUID が衝突したり作り直されたりしないか。
4. VCC 経由でパッケージを更新した場合に、既存の生成ファイルが再インポートされないか（生成ファイルはパッケージの外の `Assets/dennokoworks/SpecularExV2_Generated` にあるので、影響はない見込み）。
5. 既存PNGの再ベイクと、PNGだけを削除して再生成する場合に `.meta` のGUIDが保持され、共有マテリアルと Undo / Redo の参照が壊れないか。

検証で問題が出た場合は I を見送る。そのときは代わりに「最初のインポートの圧縮を軽くする」方法（例: 書き込みの前に最大サイズを小さくするなど）も検討するが、importer を先に作る手段は他にないため、効果は限られる。

## 5. 実装の順番とコミット単位

1. `feat(editor): パックマスク処理の計測マーカーとデバッグログ` — M
2. `perf(editor): オブジェクト変更イベントをスロット状態で絞り込み` — A
3. `perf(editor): インポート設定確認とシェーダーフォルダー解決をキャッシュ` — D, E
4. `perf(editor): 自己保存による再パック要求を抑制` — B
5. 計測シナリオ 3〜5 を測り、フェーズ1の効果を記録する。ビルドと手動更新でDを迂回することも確認する
6. `refactor(editor): シーンの監視再登録とパック検証を分離` — C。リロード後の監視復元と初回検証を確認する
7. `perf(editor): 削除時の全件確認を残して逆依存インデックスを導入` — F。初回削除、復元失敗、同一バッチの削除と再インポートを確認する
8. `perf(editor): Inspector のパック状態と検証済みマテリアルをキャッシュ` — G, H。未保存ソースと処理失敗の除外を確認する
9. シナリオ 1、2、5、6 を構築前・構築後・リロード後に分けて測り、フォールバックの有無とともに記録する
10. I の検証用ブランチ。既存GUIDの保持を含む検証結果によって採用するかを決める

コミットはそれぞれ単独で動く状態にする。こうしておけば、問題が出たときにそのコミットだけを戻せる。

## 6. 回帰確認チェックリスト

各フェーズの後に手作業で確認する。

- [ ] マスクスロットにテクスチャを割り当てると、パック画像が1回だけ生成されて割り当てられる
- [ ] ソース PNG を外部で編集して保存すると、パック画像が再生成されて差し替わる（保存済みの `.mat`・シーン埋め込みのマテリアル・FBX 埋め込みのマテリアル）
- [ ] ソーステクスチャを削除すると、そのスロットが空の状態として再パックされる（全スロットが空ならパック先も空になる）
- [ ] 生成マスクを手で削除すると再生成される
- [ ] コンパイル直後、Inspector を開かずにシーン埋め込みマテリアルのソースを編集・削除しても追従する。監視再登録前に届いたイベントも失われない
- [ ] インデックス構築前の最初のイベントとしてソース・生成マスクを削除しても全件確認で修復される（シーンで未使用の保存済み `.mat` も含む）
- [ ] インデックスの復元失敗・保存サイズ超過の後に削除しても修復され、古い保存値が再利用されない
- [ ] 同一バッチにソース削除とコンテナ再インポートが含まれていても、削除前の依存から対象が特定される
- [ ] シーン埋め込みマテリアルだけが使用する生成マスクを削除しても再生成される。コンパイル直後にも確認する
- [ ] 自己保存後も依存インデックスと監視記録が更新され、その後のソース変更・生成マスク削除に追従する。自己保存の通知がない場合や別の保存が続いた場合もイベントを誤って抑制しない
- [ ] 未保存の `Texture2D` / `RenderTexture` の内容を同じ参照のまま更新し、Watcher に再要求すると再ベイクされる
- [ ] ベイク・インポート・ロードの失敗後、次の要求で再検証される。失敗状態が検証済みキャッシュに残らない
- [ ] D・H のキャッシュがある状態でも、ビルド・NDMF・手動リビルド・「Update All Materials」は検証を省略しない
- [ ] 生成マスクのインポート設定を変更・適用すると D・H が無効化され、次の検証で必要な設定が修復される
- [ ] 既存PNGの再ベイクとPNGだけの欠損復旧で既存 `.meta` のGUIDが保持され、共有マテリアルと Undo / Redo の参照が壊れない
- [ ] スロットの変更を Undo / Redo すると、パック画像の参照も追従する
- [ ] マテリアルを複製しても、複製元と複製先の両方が正しい参照を持つ
- [ ] テクスチャやマテリアルを移動しても、再生成は起きず、参照も壊れない
- [ ] シェーダーを lilToon から SpecularExV2 に切り替えると、パック画像が生成される
- [ ] Library を削除してプロジェクトを開き直したとき（全件インポート）に、異常に遅くならず、最終的に整合が取れる
- [ ] VRCSDK でアップロードできる（NDMF あり・なし）。NDMF のクローンが元スロットを外した状態でも正しく出力される
- [ ] パッケージ（VCC）を更新しても、プロジェクト全体の再インポートが起きない
- [ ] 構築済みインデックスで計測シナリオ 1〜4 の不要な処理が減る。初回構築・削除フォールバック・シナリオ5の監視再登録と初回検証は別に計測し、残る負荷を記録する

## 7. 範囲外

- シェーダー（GPU 側）の最適化。これは `optimization_report.md` で扱う。
- 生成ファイルの自動削除。これは Undo や他のコピーから参照される可能性があるため、従来どおり手動メニューのみとする。
- `EditorApplication.update` による処理の時間分割。H を入れた後にもシーン走査が重い場合だけ検討する。
